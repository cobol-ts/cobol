# AWS public EMPREC01 fixed-block example

Source: AWS Samples, [Unlock Mainframe Data Files on AWS](https://github.com/aws-samples/unlock-mainframe-data-files-on-aws), README sections **Input Copybook**, **Input Data File** and **Output CSV**. License: MIT-0, see upstream.

- `EMPREC01.cpy`: copybook transcribed from the AWS sample, also used by `@cobol-ts/layout`'s public-copybook regression tests.
- `TEST.EMP.RECORD.FILE.csv`: published **expected** CSV rows (including spaces, leading zeroes and explicit positive/negative formatting). This is an independent decoding oracle, *not* generated by `@cobol-ts/codec`.
- `source-xxd.txt`: the original 47 lines of published `xxd -EBCDIC` hexadecimal data, with offsets. Documentation comments are our own.
- `TEST.EMP.RECORD.FILE.dat`: exactly the 750 raw bytes *transcribed from that upstream hex dump*, five FB/150 records. This was not generated by our encoding routines and was **not** a direct download of a hosted binary. The first 150 bytes agree byte-for-byte with the independent pre-existing `layout/fixtures/public/aws-emprec01.first-record.hex` fixture.

`d3850be04a9a0702c842afc506de0a7b30b88a6a99e3e8b2a06a0cbf6cf5fde2`

When updating the fixture, consult the upstream published bytes and expected values. Never regenerate these files by calling our own codec: doing so would eliminate their usefulness as an independent integration test.
